Why another rule set

Agent detection rules are easy to write and rarely maintained. Most public sets are folders of untested YAML. When the agent framework changes a field name or a provider ships a new key prefix, they go quiet and nobody notices.

  • Fixtures per rule: every malicious event must fire, every benign one must stay quiet.
  • Engine-verified: Splunk and Sentinel KQL 15/15, Elastic 13/15, with the 2 Lucene regex limits documented.
  • CI regenerates the conversions on every change, so the SIEM queries never drift from the rules.
